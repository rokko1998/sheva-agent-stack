# Review contract

The project graph is generated by Graphify. The private baseline snapshot lives under `~/.local/state/sheva-agent-stack/architecture-review/`, outside Git. `review --update` runs Graphify's AST-only update and compares graph snapshots with upstream `graph_diff`, `find_import_cycles`, `god_nodes`, and `affected_nodes`.

The bounded Jev state includes project, changed files, graph summary before/after, added/removed nodes and edges, new/removed/existing import cycles, new cross-community edges, coupling and blast-radius deltas, god-node changes, structural growth, edge confidence/provenance, explicit/matched project rules, and `reliable_policy_evidence`. The last field contains only matched EXTRACTED edges whose cited line was verified from project source. The script caps lists and flags truncation; a truncated result needs source inspection before a strong conclusion. It sends no source dump.

Optional `--rules-file` is a JSON array of `{ "source": "path:line", "text": "exact or faithful explicit rule", "matched": true|false }`. For a reliable violation, also give `role_mapping` and `matched_evidence` with `source`, `target`, `relation`, `source_file`, `source_location` (for example `L3`), `source_excerpt` (at most 200 characters), and a short explanation tying the added edge to the rule. The adapter verifies that excerpt against the cited project source line before setting `source_verified: true`; Graphify extraction alone does not perform policy interpretation. Existing project docs are the only source of normative rules. If none apply, policy compliance is NOT_APPLICABLE. No generated `.agent/architecture.md` is required.

The versioned Jev wording is in `policies/architecture-review/jev.md`. Official SystemOne returns `structural_assessment` (CLEAN/CONCERN/UNCERTAIN) and `policy_compliance` (COMPLIANT/VIOLATED/NOT_APPLICABLE/UNCERTAIN). Probabilities are telemetry. Deterministic outcome: VIOLATED → NEEDS_REVIEW; CONCERN → CONCERN; any UNCERTAIN → investigate, then NEEDS_REVIEW if unresolved; CLEAN + COMPLIANT or NOT_APPLICABLE → PASS. A VIOLATED response without a matched explicit rule and its matching extracted source-verified new edge is downgraded to UNCERTAIN.

Use `scripts/run-architecture-review review ... --no-jev` to inspect a native delta without calling Jev. The agent may then verify source locations, amend explicit rule evidence, and rerun Jev. `source_verified` is false by default; it must be supported by real source inspection before a reliable policy violation. This workflow does not block commits, roll back changes, run semantic extraction, or write knowledge memory.
