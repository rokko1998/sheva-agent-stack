# Review contract

The project graph is generated by Graphify. The private baseline snapshot lives under `~/.local/state/sheva-agent-stack/architecture-review/`, outside Git. `review --update` runs Graphify's AST-only update with the active runtime's deterministic `PYTHONHASHSEED=0` convention and compares graph snapshots with upstream `graph_diff`, `find_import_cycles`, `god_nodes`, and `affected_nodes`. Directed cycles are compared independent of their reported starting node. New edges between baseline nodes use baseline community membership; edges involving a new node are explicitly marked as relying on post-change community assignment.

The bounded Jev state includes project, changed files, graph summary before/after, added/removed nodes and edges, new/removed/existing import cycles, new cross-community edges, coupling and blast-radius deltas, god-node changes, structural growth, edge confidence/provenance, explicit/matched project rules, and `reliable_policy_evidence`. The last field contains only matches where both the explicit rule and matching EXTRACTED new edge were verified against their cited project source. The script caps lists and flags truncation; a truncated result needs source inspection before a strong conclusion. It sends no source dump.

Optional `--rules-file` is a JSON array of `{ "source_file": "docs/architecture.md", "source_location": "L12-L14", "text": "exact cited rule text", "matched": true|false }`. The adapter resolves the policy path inside the project, reads the cited line/range, and requires normalized exact text equality before marking the explicit rule verified. For a reliable violation, also give `role_mapping` and `matched_evidence` with `source`, `target`, `relation`, code `source_file`, code `source_location` (for example `L3`), `source_excerpt` (at most 200 characters), and a short explanation tying the added edge to the rule. The code excerpt is separately verified against the cited project source line. Existing project docs are the only normative source. If none apply, policy compliance is NOT_APPLICABLE. No generated `.agent/architecture.md` is required.

The versioned Jev wording is in `policies/architecture-review/jev.md`. Official SystemOne returns `structural_assessment` (CLEAN/CONCERN/UNCERTAIN) and `policy_compliance` (COMPLIANT/VIOLATED/NOT_APPLICABLE/UNCERTAIN). Probabilities are telemetry. Deterministic outcome: VIOLATED → NEEDS_REVIEW; CONCERN → CONCERN; any UNCERTAIN → investigate, then NEEDS_REVIEW if unresolved; CLEAN + COMPLIANT or NOT_APPLICABLE → PASS. The outcome layer also enforces the contract: a new cycle cannot remain CLEAN; a truncated material delta cannot remain CLEAN; an unverified VIOLATED becomes UNCERTAIN; and COMPLIANT without an applicable verified rule becomes NOT_APPLICABLE.

Use `scripts/architecture-review review ... --no-jev` to inspect a native delta without calling Jev. The agent may then verify source locations, amend explicit rule evidence, and rerun Jev. Both the explicit policy rule and matching EXTRACTED edge must be source verified before a reliable policy violation. This workflow does not block commits, roll back changes, run semantic extraction, or write knowledge memory.
